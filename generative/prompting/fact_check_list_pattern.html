🕵️ Fact Check List Pattern

The fact check list pattern makes a Large Language Model (LLM) list the discrete facts its answer relies on. Once those atomic claims are explicit, a human or a second checker can verify them and catch hallucinations early.

Why it's needed 🧭

  • Models make confident mistakes. LLMs are probabilistic text generators, so they inevitably make mistakes, confidently produce wrong statements, and sometimes emit prose that looks authoritative while lacking grounded factual support.
  • They complete patterns, not questions. They are not literal question-answer tools; they are pattern completers that approximate likely continuations.
  • Explicit claims can be checked. A structured prompt that forces the model to surface the atomic claims it relies on lets a human or an automated checker verify them, catch hallucinations early, and decide whether the response is trustworthy, instead of silently accepting polished but unfounded output.

Installing the pattern ⚙️

The goal is to force the model to externalize the factual claims it asserts, then verify them in a fresh context. Start by telling the model to append its facts to every answer.

1 Minimal prompt

UserAny time you produce a text give me the facts that you have produced.

2 Expanded, more prescriptive prompt 📐

This version says where the facts go and which facts matter: the fundamental ones that would undermine the output if any were wrong. It is shown as originally provided, including its typos.

UserWhenever you output text, generate a set of facts that are contained in the output.
The set of facts should be inserted at the end of the output.
The set of facts whould be fundamental facts that could underminde teh veracity of the output if any of them is incorrect.

Before and after 📦

The same question, answered once without the pattern and once with it installed. Both answers contain the same mistake. Only one makes it easy to find.

UserWhen was the Eiffel Tower built, and how long was it the tallest structure in the world?
Before · no fact list · ModelThe Eiffel Tower was built between 1887 and 1889 for the World's Fair in Paris. At about 330 meters, it remained the tallest man-made structure in the world until the Empire State Building was finished in 1931.
After · with the pattern · ModelThe Eiffel Tower was built between 1887 and 1889 for the World's Fair in Paris. At about 330 meters, it remained the tallest man-made structure in the world until the Empire State Building was finished in 1931.Facts: 1. The tower was built between 1887 and 1889. 2. It was built for the 1889 World's Fair in Paris. 3. It is about 330 meters tall. 4. It was the tallest man-made structure in the world until the Empire State Building (1931).

The mistake is in fact 4. In the paragraph it reads like a detail. In the list it is a single claim that you can look up.

Verify in a fresh context 🔄

3 Check the facts independently

Open a new conversation with no earlier context, so the checker can't simply agree with itself. Paste the fact list and ask the model to check it:

User · fresh conversationCheck each fact in the list below. Label it Supported or Not Supported. For every fact that is Not Supported, give the correct version.1. The tower was built between 1887 and 1889. 2. It was built for the 1889 World's Fair in Paris. 3. It is about 330 meters tall. 4. It was the tallest man-made structure in the world until the Empire State Building (1931).

4 Label, correct, repeat 🧪

Model · checker1. Supported. Construction began in January 1887 and finished in March 1889.
2. Supported. It was the entrance arch of the 1889 Exposition Universelle.
3. Supported. It is about 330 meters tall, including the antennas at the top.
4. Not Supported. The Chrysler Building in New York passed it in 1930, a year before the Empire State Building opened.

Fix the answer with the corrected fact, then run the check again until every fact is Supported.

🔐 A checker model can be wrong too. For anything that matters, confirm the Not Supported facts against a primary source, such as official documentation or a reference work.

Another example: a technical answer 💻

The pattern is especially useful for version numbers and dates, which models often mix up.

UserWhich Python version added the match statement?
Model · with the patternThe match statement arrived in Python 3.10, which was released in October 2020. It brings structural pattern matching, similar to switch in other languages but able to unpack data.Facts: 1. The match statement was added in Python 3.10. 2. It was specified in PEP 634. 3. Python 3.10 was released in October 2020.

In a fresh conversation, the same check catches the wrong date:

User · fresh conversationCheck each fact in the list below. Label it Supported or Not Supported. For every fact that is Not Supported, give the correct version.1. The match statement was added in Python 3.10. 2. It was specified in PEP 634. 3. Python 3.10 was released in October 2020.
Model · checker1. Supported.
2. Supported. PEP 634 is the specification. PEP 636 is the tutorial.
3. Not Supported. Python 3.10 was released on 4 October 2021. October 2020 was Python 3.9.
