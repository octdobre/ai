🎮 Game Play Pattern

The game play pattern turns a Large Language Model (LLM) into a Game Master (GM). You set the rules, then you and the model take turns: it sets a challenge, you respond, and it scores you before moving on. Each round shows you exactly what you got right and what you missed.

Learn a subject

Tell the model it is the GM, name the subject, and describe one turn. Here the game teaches HTTP verbs:

UserYou are the Game Master. Let's play a game that teaches me HTTP verbs. Each turn, describe one short scenario and ask which verb fits. After I answer, score me out of 10, explain what I missed in two sentences, then give me a slightly harder scenario. Stop when I say "stop".
Model · Game MasterRules confirmed: one scenario per turn, scored out of 10, each harder than the last.

Turn 1. An app lets users change only their email address and leaves the rest of the profile as it is. Which verb should the request use?
User · PlayerPUT, because we're updating the user.
Model · Game Master5/10. PUT replaces the whole resource, so any field you leave out can be wiped. PATCH sends only the fields that change.

Turn 2. A request times out and the client retries it automatically. Which verbs are safe to retry, and where does POST fall?
User · PlayerGET, PUT and DELETE are idempotent, so repeating them changes nothing extra. POST isn't, so a retry could create a second order.
Model · Game Master10/10. Exactly. That's why payment APIs ask for an idempotency key on POST requests.

Turn 3. How is HEAD different from GET, and when would you use it?

Research a solution

The same loop works for a real problem. Make the GM attack every idea you bring, and let the strongest one win:

UserYou are the Game Master of a debate game. The goal is to find the best way to let users search the 2 million products in my online store, which runs on PostgreSQL. Each turn, I propose an option. You answer with the strongest real-world objection, say whether the option survives, and update a scoreboard. Stop when I say "stop".
Model · Game MasterRules confirmed. The scoreboard is empty. Turn 1: propose your first option.
User · PlayerUse LIKE '%term%' queries on the products table.
Model · Game MasterObjection: a leading wildcard can't use a normal index, so every search reads all 2 million rows. It also can't rank results or handle typos. Doesn't survive.

Scoreboard: LIKE 0. Turn 2: your next option.
User · PlayerPostgreSQL full-text search with a GIN index.
Model · Game MasterObjection: it's fast and needs no new infrastructure, but it handles typos poorly. Adding the pg_trgm extension fixes that. Survives.

Scoreboard: Postgres full-text + pg_trgm 2, LIKE 0. Turn 3: challenge the leader or propose another option.
User · PlayerElasticsearch.
Model · Game MasterObjection: it gives the best ranking and typo handling, but it's a second system you must run and keep in sync with Postgres. At 2 million products, that cost is hard to justify yet. Survives, barely.

Scoreboard: Postgres full-text + pg_trgm 3, Elasticsearch 1, LIKE 0. Turn 4: your move.

Prompt templates

1 Minimal “Game Master” prompt

UserYou are the Game Master. Let's play a game about <topic>.
Here are my basic rules:
- Role: You are the GM; I am the player.
- Flow: Present one challenge per turn, wait for my reply, then score and continue.
- Constraints: <constraints>.
- End: Stop after <N> turns or when I say "stop".

Propose the full rules succinctly, confirm them, then start Turn 1.

2 Structured template with seed rules

UserSystem: You are a fair, concise Game Master.
User: I want a learning game focused on <topic>.
Seed rules:
1) The GM defines realistic challenges that do not require writing source code.
2) Each turn, the GM provides: (a) a challenge, (b) evaluation rubric, (c) success criteria.
3) After my reply, the GM returns: (a) outcome, (b) rationale, (c) brief coaching, (d) next turn.
4) Keep turns short and specific. Ask clarification questions sparingly.
5) Stop after <N> turns or when I say "stop".

Confirm rules, invite edits, then begin.

Example game: Prompt engineering trainer

A ready-to-paste game in which the GM sets prompting tasks and grades the prompts you write for them.

UserWe are going to play a game involving prompt engineering.
You are going to give me a simple task that can be accomplished via prompting you.
Your tasks should all have a reasoning to them; they should not require creating source code.

I will write a prompt for you to solve the task.
You will give me the output of my prompt and tell me if the prompt solved the task.
Ask me questions until I tell you to stop.
You will ask me a question, wait for my response, tell me how I did, and then ask me another question.

Ask me the first question.
