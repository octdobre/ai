⚡ Menu Actions Pattern

Define a small, explicit menu of action keywords (macro triggers). Each keyword expands into a longer instruction the model follows consistently, so you install the menu once at the start of a session and then drive it with short control words.

Why it works

  • No retyping. Formatting or process guidance lives in the menu, so you don't repeat it every turn.
  • Consistent output. Each keyword always expands into the same longer instruction, so the same trigger gives the same kind of answer.
  • Complex workflows, short messages. Once the menu is installed, you can run whole workflows by sending only short control tokens, for example ANALYZE, REFORMAT:JSON, or CRITIQUE|depth=2.

The installation prompt

Send this at the start of the session. It defines three triggers, a fallback for messages that use none of them, and a confirmation step:

prompt
Whenever I write "summary", write a paragraph summary about the input.
When I write "bulletpoint", write a bullet pointed list about the input.
When I write "mainidea", summarize into one sentence with the main idea from the input.
If my message does not start with one of those trigger words, ask me which of (summary | bulletpoint | mainidea) I want.
Confirm installation by restating the triggers in a compact table, then wait for input.

4 mainidea

Usermainidea Provide a broader paragraph about software reliability and testing.
ModelRigorous, automated testing underpins software reliability by catching regressions early and creating a repeatable safety net for change.

The trigger word wins: even though the message asks for “a broader paragraph”, mainidea keeps the answer to a single sentence.
