🛎️ Ask for Input Pattern

Give a Large Language Model (LLM) instructions for a job, and it often starts right away, guessing at what you want. The ask for input pattern makes the model pause and ask for what it is missing, such as the first task or a detail it needs. It confirms the job, says what it needs, then waits.

Why it works

  • It confirms the job first. The model restates what it will do, so you can correct a misunderstanding before any work starts.
  • It names what it needs. The model says exactly which input to send next, so you are never left guessing.
  • It waits instead of guessing. No invented example task, no made-up context, and no long answer you didn't ask for. ⏳

Example interaction 🧪

The user sets up a repeating job and ends with a request for the first task:

UserWhenever I ask you to write a prompt for me to accomplish a task, list what the task is, list alternative approaches for completing the task, and then write a prompt for yourself for each approach. When you are done, ask me for the next prompt to create alternatives for.

Ask me for the first task.

1 The waiting state 💤

ModelUnderstood. To proceed I will need your first task. When you give it, I will:
  1. Restate the task succinctly.
  2. List several distinct approaches.
  3. Generate a purpose-built prompt for each approach.
  4. Ask you if you want refinements, a combination, or a different angle.
Provide the first task.

The model does no work yet. It confirms the plan and asks for the one thing it is missing.

2 The first task 📦

UserCreate a prompt for the task “cleaning up a cluttered desk”.
ModelTask: create a prompt that guides an LLM to produce an action plan for cleaning up a cluttered desk.

Alternative approaches:
  • A) Time-boxed sprint
  • B) Categorize and conquer
  • C) Minimalist value filter
  • D) Initial overhaul plus maintenance routine
A) Time-boxed sprint promptI have a cluttered desk with mixed papers, old notes, cables, gadgets, pens and unopened mail. Create a 30-minute cleanup plan divided into 5-minute sprints. For each sprint, give the goal, the specific actions, and why it's a quick win. End with a 5-minute daily maintenance routine. Ask me if there are any sensitive documents before advising what to throw away. B) Categorize-and-conquer promptMy desk has papers, mail, sticky notes, cables, stationery and other objects. Produce a phased plan: (1) define category bins (Keep / Action / Archive / Recycle / Trash / Unsure), (2) rules for sorting each item, (3) a temporary staging layout, (4) where everything goes back, (5) a short review checklist. Ask me to confirm any category I seem unsure about. C) Minimalist value filter promptHelp me clear a cluttered desk by removing anything that doesn't support today's work. Give me (1) three value criteria, (2) a triage pass of under 10 minutes, (3) a deeper second pass, (4) steps to reset the desk's look, (5) a two-sentence reminder to stop the clutter coming back. End by asking whether I want a looser or stricter version. D) Overhaul plus maintenance promptI need a one-time overhaul and a light daily reset for a cluttered desk. Give me (1) what to prepare, (2) the overhaul steps in order with estimated minutes, (3) a description of what "done" looks like, (4) a 2-minute end-of-day reset, (5) a weekly check. At the end, ask me to rate my current clutter from 1 to 5 so you can adjust the plan. Next step: would you like to refine one, merge elements, or try a different angle? What's the next task?

The model follows the plan it announced, then ends by asking for the next input instead of stopping.

Variations 🔄

Each variation changes what the model asks for before it starts.

I Minimal deferral ⏱️

User · templateI will give you tasks. Do not solve until I supply the first one. Simply ask: "What is the first task?"

II Clarification first ❓

User · templateBefore answering, list up to 5 clarifying questions in priority order. Then ask me to answer them. Do not proceed until I reply.

III Progressive elaboration 🪜

User · templateWe will build the solution in stages: (1) goals, (2) constraints, (3) outline, (4) full draft. Request stage (1) only. After each stage, ask for the next. Do not skip ahead.

IV Input schema enumeration 🗂️

User · templateList a JSON schema of required inputs (no example values). Ask me to populate it. Wait.
