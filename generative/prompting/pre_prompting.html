🎬 Pre-Prompting

Every new chat starts blank. Without context, a Large Language Model (LLM) guesses what you are working on, so you end up repeating the same details in every question. Pre-prompting fixes this: you send a short setup message first, and every later answer builds on it.

Why it works

  • Context is set once. The model reads the setup before every later message, so you never repeat the project, the deadline, or the format.
  • Short questions get specific answers. A five-word question is enough, because the setup already fills in what the model would otherwise guess.
  • Answers keep the same shape. Every reply follows the format you asked for, so you can compare them at a glance.

Send the setup first

Open the conversation with what the model needs to know for the whole session. Here the user is planning a website launch:

User · pre-promptFor the rest of this chat, I'm planning the launch of a landing page for Brightdesk, a standing desk startup. The page goes live on 14 November, and the team is one designer and one developer. Answer every question in three short sections: Summary, Risks, Next steps.
ModelGot it. Every answer will assume the 14 November launch and a team of two, and will use Summary, Risks and Next steps. What's your first question?
UserCan we add a product video?
ModelSummary: Yes, if you use footage you already have. Shooting a new video would take the designer away from the page for days.
Risks: A large video file slows the page down on phones.
Next steps: Cut a 60-second clip by 7 November and embed it from YouTube or Vimeo instead of hosting it yourself.
UserShould we translate the page into German?
ModelSummary: Not before launch. Translating and checking the page would cost your team of two about three days.
Risks: A rushed translation reads badly to native speakers.
Next steps: Launch in English, then add German the week after with a professional translator.

Neither question mentions the date, the team, or the format, yet every answer uses all three.

Before and after

The same question, sent to a model with no setup and to the model above:

UserCan we add a product video?
Before · no pre-prompt · ModelAbsolutely! Product videos are a great way to boost engagement. Keep it under two minutes, show the product in real use, add captions for viewers watching without sound, and include a clear call to action at the end.

The model doesn't know the deadline or the team, so it gives general advice in its own format.

Another example: code review

A pre-prompt is just as useful for technical work, where every answer depends on the same project details:

User · pre-promptIn this chat, I'll paste Python code from our web service, which runs on Python 3.12. For each snippet, point out bugs first and style second, and keep each answer under 100 words.
ModelUnderstood. Paste the first snippet when you're ready.
Userdef add_tag(tag, tags=[]): tags.append(tag) return tags
ModelBug: the default list is created once and shared by every call, so tags from one request leak into the next. Create a new list inside the function instead:def add_tag(tag: str, tags: list[str] | None = None) -> list[str]: if tags is None: tags = [] tags.append(tag) return tagsStyle: the type hints above use the list[str] | None syntax that Python 3.10 and later support.

Pitfalls 🚫

  • Rules that contradict each other. “Explain in detail but keep it short” leaves the model to pick one at random.
  • A setup that's too long. A few sentences are easier to follow than a page of rules, and less likely to conflict.
  • Changing the setup halfway. If the project changes, say so clearly or start a new chat, so old details don't mix with new ones.
